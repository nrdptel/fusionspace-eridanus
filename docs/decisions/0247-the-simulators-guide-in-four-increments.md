# ADR-247: The simulator's guide in four increments, its terminal figures drawn from the CLI's own runs, and its tour ending on the median public flight (2026-10-12)

- **Status:** accepted; carries out [ADR-196](0196-the-2026-10-07-product-guides.md) §1 and §2 for the simulator, on [ADR-242](0242-the-guides-format-and-the-trust-guide.md)'s format; splits M0.8a into M0.8a1 to M0.8a4 and closes M0.8a1
- **Summary:** M0.8a, the simulator's guide, is too big for one increment, so it splits four ways, its own *done when* unchanged: the landing page and a tour of the command line (M0.8a1), the same flight from Python (M0.8a2), the *Compared with* section ADR-209 §8 asks for (M0.8a3), and the maintainer's read (M0.8a4, blocked on the maintainer). The guide is a new *Product guides* part of the site: a landing page, *HPR Sim*, and *A tour of HPR Sim*, both held to the guides' number check. The tour's pictures are terminal figures: `cargo xtask cli` draws each from the same in-process run as a regenerated example on the page, word-wrapped by the figure check's own glyph widths, with lettered balloons at the lines the text explains, and `--check` fails a stale one. The tour ends on the public flight whose unsigned apogee miss is the median of the report's, picked by that rule in code, so neither the best nor the worst flight can be chosen by hand; its logged numbers stand beside the spread over every flight.

**Context.** M0.8a's *done when*: "its landing page and tour meet all of M0.7a's bullets and
ADR-195 §7, read cold in a docs review and by Neer; the tour ends on a flight from
`validation/reports/real-flights.md`, named by case id, its measured numbers read from that report
by a test and shown beside the report's spread over every flight, no measured trace drawn without
a license entry, ERA5 drawings with Copernicus's credit; the tour has CLI terminal figures and
Python output, each regenerated by `xtask cli --check` or its docs test and failing when stale (a
test each); its *Compared with* section meets ADR-209 §8."

That is four pieces of work of different kinds: pages and a new kind of figure; the Python
package's docs test; a survey of other tools' current docs; and a read only the maintainer can
give. Nothing in the repository draws a terminal: CLI output appears as text blocks
`xtask cli --check` regenerates. The real-flights report commits derived numbers only; its logs
stay under `refs/`, and `THIRD-PARTY-NOTICES.md` records the teams' permissions as RocketPy's
notebooks state them, which cover the numbers the report derives, not a redrawn trace.

**Decision.**

1. **Four increments.** M0.8a keeps its *done when* word for word, and closes when its four
   increments have:
   - **M0.8a1, the landing page and the CLI tour:** both pages meet M0.7a's bullets but the
     maintainer's read, read cold in a docs review; the tour ends on the report's median flight
     (§4), by case id, its logged numbers read by a test beside the spread over every flight;
     its terminal figures are drawn from `xtask cli`'s runs, and `--check` fails a stale one (a
     test).
   - **M0.8a2, Python in the tour:** the tour flies the same rocket from Python, its output
     regenerated by the package's docs test, which fails when it is stale (a test).
   - **M0.8a3, *Compared with*:** the section ADR-209 §8 asks for.
   - **M0.8a4, the maintainer's read,** blocked on the maintainer, as M0.7a6 is for the four guides
     ([ADR-245](0245-the-drag-guide.md)).
2. **Where the guide lives.** A *Product guides* part of `SUMMARY.md`, after *Accuracy* and before
   *Rocketry explained*: *HPR Sim* (`the-simulator.md`), the landing page, with *A tour of HPR Sim*
   (`simulator-tour.md`) under it. Both are in `guides()`, so every number in their text is a
   quote from a committed report or sits in a regenerated block, and the tour is in `cli.rs`'s
   list of pages whose examples it runs. The landing page says what HPR Sim is, who it is for,
   how far to trust it and how to install it, and points to the tour and the task pages; it
   doesn't repeat them.
3. **Terminal figures, drawn from the CLI's own runs** (`xtask/src/cli/terminal.rs`). A figure is
   named in `cli.rs` by its page, its command, its file and its callouts. `cargo xtask cli` runs
   the command in-process, as it runs the page's examples, and draws what it printed: the
   command line after a prompt, then each line of output on a white panel, in Cascadia Mono, each
   line word-wrapped to the panel by the figure check's own glyph widths, so nothing it draws can
   leave the frame, and wrapped lines indented as a terminal continues them. Rules:
   - the page must hold an example of the same command, so the picture and the text a reader
     can copy or search come from the same program and agree; a figure whose command opens no
     example on its page fails;
   - each callout is a letter in a balloon, in the gutter left of the first line that starts with
     its text, joined to it by a leader; a callout whose line the run doesn't print fails, so a
     renamed output line can't drop a balloon unnoticed. Letters, not numbers, so the prose that
     explains them holds no number the guide check would have to quote;
   - labels stay in the prose: the figure holds the run and the letters, nothing else;
   - each figure passes the figure and drawing checks before it is written, and `--check` fails
     a committed figure the command no longer draws.
4. **The tour ends on the median public flight.** The flight is picked in code, as the one whose
   unsigned apogee miss is the median of the report's (the lower of the two middle ones if the
   count is even); on today's report that is Genesis, EuRoC 2023, which read low, the side that
   flatters a ceiling. The tour names it by its case id, gives its logged apogee and time to
   apogee beside HPR Sim's, and then the spread over every flight in the report: the least and the
   largest miss, the mean without signs and with them. A rerun of the report that moves the
   median, or any of these numbers, fails the page. The tour draws no measured trace, so no
   license entry is needed for one; its numbers come from ERA5 weather, so the page carries
   Copernicus's credit as the trust guide does.
5. **What the tour shows** is the simulator's main path on the guide rocket the how-to guides fly:
   fly a design file and read what it prints (a terminal figure), scatter its inputs with
   `hpr mc` (a terminal figure), then the public flight. Each step links to its task page for the
   detail.

**Alternatives considered.**

- **One increment.** Rejected: the Python output and the comparison survey are separate work,
  and the maintainer's read can't be met in a session; one increment would stay open for both.
- **A terminal figure in place of the text block.** Rejected: a reader can't copy, search or read
  aloud text in an image, and the guide check reads inline code against the regenerated text on
  the page. The figure and the block come from the same run instead.
- **Cropping long output to a window.** Rejected: a crop is a clip, and the project's rule is
  that nothing is cut off; long lines wrap.
- **A flight picked by hand.** Rejected: the best one flatters and the worst one alarms; the median
  by rule is the honest middle, and the spread beside it shows the rest.
- **Drawing the median flight's logged trace.** Rejected: the permissions recorded cover derived
  numbers, not a redrawn log.

**Consequences.**

- A change to what `hpr sim` or `hpr mc` prints fails `cargo xtask cli --check` until the
  examples and the figures are rewritten by `cargo xtask cli`, as the examples already did.
- A rerun of the real-flights report that moves the median names another flight, and the tour
  fails until it follows.
- M0.8a2 to M0.8a4 stay in the roadmap under M0.8a; the parent closes with the last of them.
